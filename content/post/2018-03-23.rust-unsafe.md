本质上，静态分析是保守的，有时候需要一些代码但rust安全规则不允许，unsafe放开规则的限制，让你自己保证安全性

计算机底层硬件有内在的不安全性，

当面向底层系统编程时，

与操作系统交互或者编写操作系统时，

与其他语言交互时，

这些情况下，有些操作unsafe操作是必须的，需要关注更多的实现细节，不仅因为性能，更重要的，这些细节关乎正确与否的问题。

rust可以认为是两种语言的联合体：Safe Rust and Unsafe Rust

Safe rust是真正的rust，不需要担心任何类型安全或者内存安全性。不会导致任何未定义行为(undefined behavior)

可以使用#![forbid(unsafe_code)]来禁止unsafe代码块

通过unsafe代码块标记，以下是四种unsafe操作，不会被编译器检查

1. Dereferencing a raw pointer，解引用裸指针

2. Calling an unsafe function or method，调用unsafe的函数

3. Accessing or modifying a mutable static variable，访问或者修改可变静态变量

4. Implementing an unsafe trait，实现unsafe trait

尽可能少的使用unsafe代码，一旦出现内存安全问题，只需要诊断unsafe部分的代码，因为其他部分已经保证了安全性

为了尽可能的隔离unsafe代码，应该通过安全抽象封装unsafe代码，并提供safe api

标准库中基于unsafe代码的安全抽象已经通过了验证

裸指针

- 裸指针允许忽略借用规则，可以同时有不可变及一个或者多个可变指针，指向同一位置

- 不保证指向有效的内存

- 允许为null

- 没有实现自动释放

可以在安全代码中创建裸指针

通过引用创建裸指针

```rust
let mut num = 5;
let r1 = &num as *const i32;
let r2 = &mut num as *mut i32;
```

通过内存地址创建裸指针

```rust
let address = 0x012345usize;
let r = address as *const i32;
```

但是解引用裸指针必须在unsafe块中

```rust
let mut num = 5;
let r1 = &num as *const i32;
let r2 = &mut num as *mut i32;
unsafe {
println!("r1 is: {}", *r1);
println!("r2 is: {}", *r2);
}
```

裸指针的主要用途之一是用于和c代码交互，另一个用途是用来构建一些borrow checker不允许的安全抽象

- 调用不安全的函数

```rust
unsafe fn dangerous() {}
unsafe {
dangerous();
}
```

[Creating a Safe Abstraction Over Unsafe Code](https://doc.rust-lang.org/book/second-edition/ch19-01-unsafe-rust.html#creating-a-safe-abstraction-over-unsafe-code)

以下是标准库的split_at_mut函数的示例

```rust
use std::slice;
fn split_at_mut(slice: &mut [i32], mid: usize) -> (&mut [i32], &mut [i32]) {
let len = slice.len();
let ptr = slice.as_mut_ptr();
assert!(mid <= len);
unsafe {
(slice::from_raw_parts_mut(ptr, mid),
slice::from_raw_parts_mut(ptr.offset(mid as isize), len - mid))
}
}
unsafe的错误用法，回到导致任意的内存访问，程序可能会crash或者出现segfault
use std::slice;
let address = 0x012345usize;
let r = address as *mut i32;
let slice = unsafe {
slice::from_raw_parts_mut(r, 10000)
};
```

因此需要非常小心的使用unsafe代码，并确保内存安全

[extern Functions for Calling External Code are Unsafe](https://doc.rust-lang.org/book/second-edition/ch19-01-unsafe-rust.html#extern--functions-for-calling-external-code-are-unsafe)

```rust
extern关键字，创建或者使用oreign Function Interface (FFI)
extern "C" {
fn abs(input: i32) -> i32;
}
fn main() {
unsafe {
println!("Absolute value of -3 according to C: {}", abs(-3));
}
}
```

"C"表示外部函数使用的application binary interface (ABI) ，c语言abi是比较通用的

由于外部函数rust无法保证安全性，所以需要unsafe标记，并由你来确保外部函数是安全的

```rust
[Calling Rust Functions from Other Languages](https://doc.rust-lang.org/book/second-edition/ch19-01-unsafe-rust.html#calling-rust-functions-from-other-languages)
#[no_mangle]
pub extern "C" fn call_from_c() {
println!("Just called a Rust function from C!");
}
```

- [Accessing or Modifying a Mutable Static Variable](https://doc.rust-lang.org/book/second-edition/ch19-01-unsafe-rust.html#accessing-or-modifying-a-mutable-static-variable)

全局变量

```rust
static HELLO_WORLD: &str = "Hello, world!";
fn main() {
println!("name is: {}", HELLO_WORLD);
}
static变量可以是可变的，访问和修改static变量都是unsafe，多线程访问会导致数据竞争
static mut COUNTER: u32 = 0;
fn add_to_count(inc: u32) {
unsafe {
COUNTER += inc;
}
}
fn main() {
add_to_count(3);
unsafe {
println!("COUNTER: {}", COUNTER);
}
}
```

可变数据的跨线程访问是困难的，需要使用并发相关的技术和线程安全的指针

- [Implementing an Unsafe Trait](https://doc.rust-lang.org/book/second-edition/ch19-01-unsafe-rust.html#implementing-an-unsafe-trait)

Unsafe trait中的方法有一些编译器无法验证的不变式，因此使用unsafe标记来保证我们自己维护了这些不变式

```rust
unsafe trait Foo {
// methods go here
}
unsafe impl Foo for i32 {
// method implementations go here
}
```
