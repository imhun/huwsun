Dada 里没有 `Arc`。共享是个内建运算符：

<!-- more -->

```dada
let ch = Character("Tzara", "Dadaist", 22)
let ch1: shared Character = ch.share
      #  ------                -----
      # share 消费掉 ch，返回同一个对象，权限变成 shared
```

`shared` 值可以随便复制，复制是浅拷贝。真正的关键在这一条**传播规则**：

> 访问 shared 对象的字段，拿到的是该字段的 **shared 浅拷贝**。

所以从 `shared Character` 取 `.name` 得到 `shared String`，从 `shared Vec[String]` 取元素得到 `shared String`。

写成 Rust 的等价物，就是从 `Arc<Vec<String>>` 里直接取出 `Arc<String>`。Rust 做不到——只能这样：

```rust
fn create_character_sheet_widget(ch: Arc<Character>) -> CharacterSheetWidget {
    CharacterSheetWidget {
        // 深拷贝字符串，再新建一个 Arc
        name: Arc::new(ch.name.clone()),
        ...
    }
}
```

这种落差在 Rust 里很常见，解法就那么几种，都不舒服：

| 解法 | 代价 |
|---|---|
| 克隆数据 | 数据不大就算了 |
| 改数据结构，比如让 `Character` 直接存 `Arc<String>` | 连锁反应：`ch.name.push_str(...)` 写不了，得改用 `Arc::get_mut` |
| 写辅助函数，`opt.as_ref()`、`&**r` 这类 | 记一堆转换写法 |

## 怎么实现的

布局上没什么魔法。每个对象开头多一个隐藏字段 `_flag`：1 表示不共享，2 表示共享。堆分配的对象在真实数据之前（-4 偏移）放引用计数。

```text
[栈]                        [堆]
ch: Character {
    _flag: 2  👈 shared
    name: String {
        _flag: 1         { _ref_count: 1
        buffer: ──────────► 'D' ...
        initialized: 7
        capacity: 8       }
    }
    klass: ...
    hp: 22
}
```

两种操作就是全部：

```text
ch2 = ch1        → 拷贝所有字段；因为 _flag == 2，递增堆数据的引用计数
let name = ch1.name
                 → 拷贝那个字段；把新对象的 _flag 设为 2；递增堆数据的引用计数
```

## 代价和收益

Dada 对做法有硬性规定：每个对象（至少带堆分配字段的那些）都有 `_flag`，每次堆分配都带引用计数。

作者给自己定的规则是：基本操作允许做“浅”操作——切换 `_flag`、调整各字段上的引用计数；但不允许做需要遍历堆结构的“深”操作。

付出这点运行时开销，换来的是权限流动得自然得多，而且语义等价的类型（能做同样的事）内存布局也一致。他把 Dada 叫“**有主见的 Rust**”：Rust 给一堆自由度让你自己选，Dada 直接把约定定下来。

顺带一句：这一整套都还没实现，是作者照着自己的笔记本写的。
